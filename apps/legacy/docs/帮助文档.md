## 1. 快速开始

### 1.1 部署（镜像模式，推荐）

```bash
git clone https://github.com/chensnails/FeedLore.git
cd FeedLore
cp .env.example .env

# 生成强随机数据库密码与更新令牌（不要用默认值上线）
sed -i "s#^PG_PASSWORD=.*#PG_PASSWORD=$(tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 32)#" .env
sed -i "s|^WATCHTOWER_HTTP_API_TOKEN=.*|WATCHTOWER_HTTP_API_TOKEN=$(openssl rand -hex 32)|" .env

grep -E '^(PG_PASSWORD|WATCHTOWER_HTTP_API_TOKEN)=' .env   # 确认已写入并记下来
docker compose -f docker-compose.release.yml up -d
```

打开 `http://<主机IP>:3210`，用 `.env` 里的 `ADMIN_USER / ADMIN_PASS`（默认 `admin / admin`）登录。

> **上线第一件事**：进「设置 → 账号」把默认密码改掉。`.env` 里的 `ADMIN_PASS` 只在首次建库时生效，改它不会改已有账号。

### 1.2 部署（源码模式，二次开发用）

```bash
cp .env.example .env
sed -i "s#^PG_PASSWORD=.*#PG_PASSWORD=$(tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 32)#" .env
docker compose up -d --build
```

两种模式的容器名、数据库卷、网络完全一致，可随时互切，数据零迁移（切之前备份数据卷）。

### 1.3 上手两步

1. **加订阅**：「设置 → 数据源」粘贴 RSS / Atom 地址 → 保存（会立即试抓一次）；已有 OPML 就点「导入 OPML」。
2. **开始读**：回「文章」页，左侧点频道 → 右侧点标题展开全文。

### 1.4 反代与 HTTPS（建议）

在 1Panel / Nginx / Caddy 里把域名反代到 `127.0.0.1:3210`，挂上证书即可。HTTPS 下才能「添加到主屏幕」，且会话 Cookie 不会被明文传输。

反代后如果需要按真实客户端 IP 做登录限流，确认反代传了 `X-Forwarded-For`；不确定就保持默认（直连方是内网/回环时自动信任）。

## 2. 界面导览

### 2.1 三个视图

| 视图 | 入口 | 用途 |
|---|---|---|
| **文章** | 顶栏视图切换 / `⌘K` | 按频道读文章，主战场 |
| **卡片** | 同上 | 网格 / 列表浏览资源卡片，点开看详情 |
| **日报** | 同上（未启用日报时入口消失） | 查看 AI 生成的每日简报 |

### 2.2 顶栏（每个视图各自一条）

| 位置 | 按钮 | 作用 |
|---|---|---|
| 左 | `≡` | 打开 / 收起频道列表（窄屏是抽屉） |
| 左 | 频道名 / 「全部频道」下拉 | 快速换频道 |
| 中 | 标题 | 当前在看什么（如「分组 · TG 频道」「未读」「关注」） |
| 右 | 单篇 / 多篇 | 手风琴模式：展开一篇是否自动收起上一篇 |
| 右 | 全部已读 | 把**当前筛选结果**全部标为已读 |
| 右 | 全部收起 | 收起所有展开的正文 |
| 右 | 🔍 | 搜索（窄屏默认收起成图标） |
| 右 | `⋮` | 刷新、夜间模式、设置；卡片页额外有「排序」子菜单与「网格 / 列表」切换；窄屏时上面三个动作也收进这里 |

> ≤720px 时「单篇 / 多篇 · 全部已读 · 全部收起」会收进 `⋮` 菜单，顶栏只留 `≡`、标题、搜索、视图切换、`⋮`。

### 2.3 命令面板

按 `⌘K`（Windows / Linux 用 `Ctrl+K`）呼出，可搜中文或拼音首字母。包含：

- **视图**：切到文章 / 卡片 / 日报页
- **主题**：四套主题快速切换
- **设置**：直达某个设置分区
- **阅读范围**：全部 / 未读 / 收藏
- **操作**：重新拉取、聚焦搜索、回到顶部、导出 OPML
- **跳转到频道**：输入频道名直达

`↑ ↓` 选择、`↵` 执行、`Esc` 关闭。这是全站唯一的键盘快捷键（其余快捷键已在 1.7.1 移除）。

### 2.4 窄屏

- 频道栏变成抽屉：点 `≡` 打开，点遮罩 / 关闭键 / 左滑关闭；
- 弹层整屏推入，可下拉手势关闭；
- 卡片墙与文章页共用同一套筛选逻辑。

## 3. 订阅管理

入口：**设置 → 数据源**（管理员还能看到「采集参数」与「图片缓存」两块）。

### 3.1 添加频道

1. 「设置 → 数据源」→ 在输入框粘贴 RSS / Atom 地址 → 保存；
2. 系统会**立即试抓一次**：成功则出现标题与图标，失败会在该行标注「抓取失败」并给出原因；
3. 可顺手填分组名（不填就是「未分组」）。

### 3.2 导入 / 导出 OPML

- **导入**：点「导入 OPML」选文件。会保留分组、文件内去重、与现有库去重，完成后回包告诉你「新增 N 个 / 重复 M 个」。
- **导出**：点「导出 OPML」，或命令面板搜「导出 OPML」，浏览器下载 `feedlore-subscriptions-日期.opml`。

### 3.3 编辑频道

每个频道行可做：

| 操作 | 说明 |
|---|---|
| 重命名 | 只改显示名，不影响抓取 |
| 改订阅地址 | 填新地址后保存，系统会立即按新地址试抓一次 |
| 改分组 | 下拉选择已有分组，或输入新分组名 |
| 单独抓取频率 | 留空 = 跟随全局（默认 30 分钟） |
| 采集开关 | 关掉 = 不再定时抓取（历史条目保留） |
| 卡片开关 | 关掉 = 该频道条目不在卡片墙出现（文章页照常） |
| 立即抓取 | 手动触发一次 |
| 删除 | 连带删除该频道的条目，不可撤销 |

**排序**：拖动手柄可组内重排，也可拖到别的分组；也可以在「序号」里填数字（两种方式并存）。

### 3.4 抓取失败怎么办

- 连续失败达阈值（默认 5 次，可在采集参数里设 2~20）→ 频道**自动停用**，行上标「抓取失败」；
- 点「立即抓取」重试，成功会自动恢复启用；
- 常见原因：源站换域名（改订阅地址即可）、源站 403（防盗链 / UA 拦截）、证书过期、源站已停更。
- 详情看「设置 → 状态 → 抓取」里的失败清单与最近一次结果。

### 3.5 采集参数与图片缓存（仅管理员）

「设置 → 数据源」底部的「采集参数」是**站点级**设置，对所有人生效：

| 项 | 默认 | 说明 |
|---|---|---|
| 自动抓取 | 30 分钟 | 全局抓取间隔（5 分钟 ~ 24 小时），单频道可覆盖 |
| 每频道保留 | 300 条 | 20 ~ 5000 |
| 最长保留 | 不限 | 按天数清理，0 = 只按条数 |
| 抓取超时 | 25 秒 | 单次抓取的上限 |
| 抓取并发 | 3 | 同时抓几个频道；调大更容易被源站限流 |
| 连续失败自动停用 | 5 次 | 2 ~ 20，成功一次即自动恢复 |
| 出网代理 | 空 | 需要经代理访问外网时填 |
| 页面自动刷新 | 关闭 | 打开后页面按间隔重新读列表（**不会**额外触发服务端抓取） |
| 图片回源窗口 / 保留 / 最长边 / 质量 | 7 天 / 90 天 / 1280 px / 78 | 图片缓存策略，另有「清空缓存」按钮 |

## 4. 阅读

### 4.1 选范围

左侧频道栏自上而下：**品牌区 → 频道搜索 → 全部文章 / 未读 / 收藏 / 关注（同一排）→ 分组与频道 → 屏蔽（分隔线置底）→ 添加频道**。

- 点「未读」「收藏」切换范围，再点一次回到「全部」；
- 点「关注」或「屏蔽」进入跨频道聚合视图，再点一次退出；
- 范围与虚拟视图可叠加（例如「未读 + 关注」）；
- 频道栏顶部的「搜索频道…」只过滤左侧列表，不影响右侧文章搜索。

> 「屏蔽」刻意放在最底部，与「关注」分开：它是「被规则挡住的内容」，不该和正常入口混排。

### 4.2 分组

- 点分组名 = 收起 / 展开该组（组名前有折叠箭头）；
- 点分组右侧**漏斗** = 只看这个分组（标题变成「分组 · 组名」，漏斗高亮）；再点一次取消；
- 频道栏顶部有「全部收起 / 展开全部分组」按钮；
- 分组内频道数会显示当前范围下的条数。

### 4.3 读一篇

- 点标题展开全文，再点一次收起；
- 正文图片点一下看大图，多图可用 `←` `→` 或按钮翻看；
- 每条右侧动作：复制链接、打开原文、收藏（星标）；
- 「单篇 / 多篇」决定展开新文章时是否收起上一篇。

### 4.4 标记

| 动作 | 结果 |
|---|---|
| 展开正文 | 自动标记为已读 |
| 点星标 | 收藏 / 取消收藏（左侧出现主色竖条） |
| 「全部已读」 | 当前筛选结果全部标为已读（在关注/屏蔽视图里只作用于命中条目） |

### 4.5 搜索

- 点 🔍 展开搜索框，输入即搜（服务端检索标题 / 摘要 / 正文 / 标签）；
- 与当前频道、范围、虚拟视图**叠加**生效；
- `Esc` 先清空关键词、再收起搜索框（避免「看不见却还在过滤」）；
- 关掉搜索框会一并清掉关键词。

### 4.6 滚动与加载

- 滚动到底自动续拉下一页，无「加载更多」按钮；
- 一屏没装满时会自动继续拉，直到填满或没有更多；
- 展开一篇新文章会自动把它顶到内容区顶部，上下翻都一致；
- 地址栏记录当前文章（`#reader/art/<id>`），刷新能回到那一条。

## 5. 卡片墙

### 5.1 浏览与筛选

- 顶部频道下拉选频道（默认「全部频道」）；
- 🔍 搜索关键词；
- `⋮` 菜单里切**网格 / 列表**、选**排序**（最新 / 最早 / 名称）；
- 滚动到底自动续拉。

### 5.2 卡片详情

点卡片弹出详情：

- 正文（含原文标签）；
- 动作行：**收藏** · **在文章页查看** · **打开原文** · **复制链接**；
- 点「在文章页查看」会切到文章页、滚到那一条并短暂描边高亮，方便对照上下文。

### 5.3 卡片开关

某个频道不想出现在卡片墙：**设置 → 数据源 → 该频道的「卡片」开关关掉**。文章页不受影响。

## 6. 关注 / 屏蔽（关键词规则）

入口：**设置 → 规则**。

### 6.1 建规则

每条规则包含：

| 字段 | 说明 |
|---|---|
| 名称 | 便于自己识别，如「AI 前沿」 |
| 类型 | **关注** 或 **屏蔽** |
| 关键词 | 一行一个；子串匹配、不区分大小写；最多 50 个，每个 ≤60 字 |
| 推送 | 仅关注规则有效：命中时是否发 Webhook |
| 启用 | 临时停用但保留规则 |

规则总数上限 30 条。

### 6.2 什么时候生效

- 保存后**只对之后新抓取的文章生效**；
- 想让已有文章也打上标记，点「应用到已有文章」（会先确认；规则有未保存改动时会拦下，要求先保存）；
- 同时命中关注与屏蔽 → **按屏蔽处理**；
- 被屏蔽命中的条目会自动标为已读。

### 6.3 在哪里看

- 频道栏的「关注」「屏蔽」两个虚拟视图（可再点一次退出）；
- 可与未读 / 收藏叠加；
- 条目仍留在原频道，不会从原列表消失。

### 6.4 Webhook 通知

- 在「设置 → 规则」底部填一条全局 Webhook 地址（POST JSON）；
- 只有勾了「推送」的**关注**规则会触发；
- 同一轮抓取的多条命中会**合并成一条消息**（标题 + 来源 + 链接）；
- 发送失败只记日志，不影响抓取；
- 地址要做公网校验：指向 `127.0.0.1` / `192.168.x.x` 等内网会被拒绝（除非部署时开了 `ALLOW_PRIVATE_HOSTS=1`）。

### 6.5 示例

| 场景 | 类型 | 关键词 |
|---|---|---|
| 只关心 AI 与模型 | 关注 | `GPT` / `Claude` / `大模型` / `推理` |
| 屏蔽剧透 | 屏蔽 | `剧透` / `结局` |
| 关注某公司动态 | 关注 | `英伟达` / `NVIDIA` |

## 7. 条目过滤（只收 / 屏蔽）

入口：**设置 → 账号 → 条目过滤规则**（折叠区，点开即可编辑）。

与关注/屏蔽的区别：**过滤是在写库前拦截**，被屏蔽的条目根本不会出现在任何列表；关注/屏蔽只是打标聚合。

| 项 | 说明 |
|---|---|
| 动作 | **屏蔽**：命中即丢弃；**只收**：仅保留命中的（白名单） |
| 匹配范围 | 标题 / 摘要 / 正文 / 全部 |
| 匹配方式 | 关键词（不区分大小写）或正则（如 `v\d+\.\d+`） |
| 规则数 | ≤ 50 条，单条 ≤ 200 字 |
| 执行顺序 | 两者同存时**先按屏蔽拉黑，再按只收拉白** |
| 生效范围 | 仅之后新抓的条目；已入库的历史文章不动 |
| 隔离 | 每个账号独立，互不影响 |

**操作**：点「添加规则」→ 选动作 / 范围 / 方式 → 填模式 →「保存规则」。非法正则会在保存时被丢弃，回包会提示丢弃了几条。

> 「只收」规则要谨慎：一旦设了只收，未命中的新条目都会被丢弃，且不会自动补回。

| 项 | 选项 |
|---|---|

## 9. AI 日报

日报是**可选功能**，不配也能用其它全部功能。

### 9.1 先配模型（设置 → 模型）

| 字段 | 说明 |
|---|---|
| 接口地址 | 兼容 OpenAI Chat Completions 的地址，如 `https://api.openai.com/v1` |
| API Key | 保存后加密落库，页面只显示掩码 |
| 模型名 | 如 `gpt-4o-mini`、`deepseek-chat` |

填完点「测试连通」，返回成功才算配好。**没有站点级默认值**：每个账号各填各的。

> 地址要能公网访问；指向 `127.0.0.1` / 内网会被拒绝，除非部署时设了 `ALLOW_PRIVATE_HOSTS=1`（本机 Ollama / vLLM 场景）。

### 9.2 再配日报（设置 → 日报）

| 字段 | 默认 | 说明 |
|---|---|---|
| 自动生成 | 关 | 打开后按设定时间每天生成 |
| 生成时间 | — | **北京时间**；服务进程得在那个点活着，错过不补 |
| 摘要范围 | 仅「采集」开启的频道 | 也可选全部频道或自定义勾选 |
| 纳入频道 | — | 仅「自定义」时出现 |
| 每频道条数上限 | 20 | 1 ~ 100 |
| 总量上限 | 150 | 控制长度与成本 |
| 保留天数 | 30 | 超期日报自动清理 |
| 写作风格 | 空 | 自定义提示词，如「简洁、要点式、突出数据」 |

### 9.3 生成与查看

- 切到「日报」页 →「生成摘要」；首次约 30~60 秒，别关页面；
- 已有当日结果时按钮变「重新生成」（忽略缓存重跑）；
- 页面顶部显示生成时间与统计（保留条数 / 频道数）；
- 页面底部有「摘要由大模型生成，可能存在偏差，请以原始条目为准」的提示。

### 9.4 生成失败的常见原因

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示模型未配置完整 | 地址 / Key / 模型名缺一 | 回「设置 → 模型」补齐 |
| 401 / 403 | Key 错、过期、余额不足 | 换 Key 或充值 |
| 连接超时 | 地址不通、被墙、服务未启动 | 用「测试连通」排查 |
| 400 model not found | 模型名拼错 | 按服务商文档填 |
| 返回内容为空 | 过去 24 小时没有新条目 | 换范围或等有更新 |

## 10. 账号与用户

### 10.1 改自己的账号

「设置 → 账号」可改用户名与密码，需要输入当前密码确认。同一页往下还有「条目过滤规则」（见第 7 节）。

### 10.2 管理员建号

「设置 → 账号」下方（仅管理员可见）：

- **新建用户**：填用户名、密码、角色（`user` / `admin`）；
- **改角色 / 重置密码**：在用户行上操作；
- **删除用户**：连带其订阅与条目，不可撤销。

### 10.3 隔离规则

- 每人独立订阅源、已读、收藏、外观、规则、模型、日报；
- 同一 URL 被两人订阅互不影响；
- 没有开放注册，也没有邀请链接。

## 11. 状态与更新

### 11.1 状态页（管理员）

「设置 → 状态」每 30 秒刷新，包含：

- 运行时长、条目 / 频道 / 用户计数、数据库体积；
- 上次抓取结果（新增 / 失败 / 耗时）、失败频道清单、自动停用阈值与当前停用数；
- 日报状态（上次生成时间、是否有错误）；
- 「复制诊断信息」：一键把上面这些复制到剪贴板，报问题时直接贴。

### 11.2 检查更新 / 一键更新

- 「设置 → 关于」显示当前版本；
- 「检查更新」向 GitHub 查最新 Release（结果缓存 10 分钟）；
- 镜像 + Watchtower 模式下，管理员会在有新版本时看到「一键更新」：点击后容器重启，页面轮询版本号直到变化（约 1~2 分钟，期间页面短暂不可用，登录态不受影响）；
- 不点也行：Watchtower 每 5 分钟自动检查并更新到 `latest`。

> 只有**正式版**（三段式 `vX.Y.Z`）会推 `latest`。预发布（`vX.Y.Z-testN`）只出带版本号的镜像，线上不会自动升级。

## 13. 常见问题

**Q：别人能看到我的订阅吗？**
不能。频道、条目、已读、收藏全部按账号隔离，接口层面跨账号访问一律 404。

**Q：图片裂了怎么办？**
图片统一走 `/api/img` 代理。先到「设置 → 状态」看失败频道；单张裂图多是源站失效或防盗链。管理员清理缓存：设置 → 数据源 → 图片缓存 →「清空」。

**Q：数据怎么备份？**
备份 PostgreSQL 数据卷（`docker compose` 里的 `db` 服务）。迁移时把卷一起搬走即可；也可以定期导出 OPML 保存订阅清单（不含已读与收藏）。

**Q：能开注册给朋友用吗？**
没有开放注册。管理员在「设置 → 账号」为每人建号，彼此数据隔离。

**Q：为什么端口改了没生效？**
改 `.env` 的 `HOST_PORT` 后需要 `docker compose up -d` 重建容器。

**Q：改了 `.env` 里的抓取间隔，为什么没用？**
采集 / 图片 / 初始化账号这类参数**只在首次建库时写入**，之后一律以页面「设置」为准。要改请到「设置 → 数据源 → 采集参数」。

**Q：日报能不发到外部吗？**
能。日报只是调用你自己填的模型地址，不经过任何第三方中转；不配模型就完全不产生外部请求。

**Q：为什么订阅地址填 `192.168.x.x` 报「不允许访问内网地址」？**
1.7.2 起默认禁止服务端访问内网（防 SSRF）。自建 FreshRSS 等场景，在 `.env` 设 `ALLOW_PRIVATE_HOSTS=1` 并重启。

**Q：忘了管理员密码？**
如果还有另一个管理员账号，用它重置；否则只能进数据库改（`users.password_hash` 由 scrypt 生成，不能直接写明文）。建议保留两个管理员账号。

**Q：演示站能长期用吗？**
不能。演示库会重置，请自托管。

## 14. 故障排查手册

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 打不开首页 / 502 | 容器未起、端口被占、反代配置错 | `docker ps` 看容器状态；`curl 127.0.0.1:3210/api/health`；查反代 upstream |
| `/api/health` 返回 503 | 数据库不可用 | 看 `db` 容器日志与卷权限；恢复后自动转 200 |
| 登录一直「用户名或密码错误」 | 字段名错（必须是 `username`/`password`）、真的错了 | 用页面登录；API 调用注意字段名 |
| 登录提示「尝试次数过多」 | 该「IP + 用户名」组合连错 6 次被锁 | 等 60 秒（逐次翻倍，最长 15 分钟），或换账号 |
| 所有频道抓取失败 | 出网被阻断 / 代理配置错 / DNS 异常 | 到「设置 → 数据源」点「立即抓取」看错误；检查出网代理 |
| 某个频道一直失败 | 源站换域名、403、证书过期、停更 | 改订阅地址；必要时删除该频道 |
| 卡片墙某频道没内容 | 该频道「卡片」开关关着 | 设置 → 数据源 → 打开「卡片」 |
| 点分组没反应 / 折叠不生效 | 1.7.2 的已知回归 | 升级到 **1.7.3** 及以上 |
| 展开文章后位置跳动 | 旧版本滚动测量时机问题 | 升级到 1.7.1 及以上 |
| 日报生成超时 | 模型地址慢或被墙 | 测连通、换地址或换模型 |
| 静态资源 404 / 样式错乱 | CDN 缓存了旧 HTML 与新资源不匹配 | 强制刷新；确认部署版本一致 |
| 更新后版本号没变 | watchtower 未到轮询点 / 未拉 latest | 等 5 分钟，或用「一键更新」；`docker exec feedlore node -e "console.log(require('/app/package.json').version)"` 查实际版本 |

**取诊断信息**：管理员「设置 → 状态」→「复制诊断信息」；或

```bash
docker compose logs --tail=200 app
curl -s http://127.0.0.1:3210/api/health
```

## 15. 备份与迁移

### 15.1 备份

```bash
# 1) 数据库（推荐，逻辑备份）
docker compose exec db pg_dump -U feedlore feedlore | gzip > feedlore-$(date +%F).sql.gz

# 2) 或者直接备份数据卷目录（停容器后拷贝更稳）
docker compose stop app
docker run --rm -v feedlore_pgdata:/data -v "$PWD":/backup alpine tar czf /backup/pgdata-$(date +%F).tgz -C /data .
docker compose start app
```

### 15.2 恢复 / 迁移

```bash
# 新机器：起 db，导入 dump
gunzip -c feedlore-2026-10-29.sql.gz | docker compose exec -T db psql -U feedlore feedlore
# 然后起 app
docker compose up -d app
```

迁移到新机器时三件事要一起带走：**数据库**、`.env`（尤其 `PG_PASSWORD` 与 `WATCHTOWER_HTTP_API_TOKEN`）、反代配置。

### 15.3 只备份订阅

「设置 → 数据源 → 导出 OPML」。只含频道与分组，不含已读 / 收藏 / 规则。

## 16. 环境变量速查

| 变量 | 作用 | 何时改 |
|---|---|---|
| `HOST_PORT` | 宿主机端口 | 端口冲突时 |
| `PG_PASSWORD` | 数据库密码 | 部署前必改 |
| `ADMIN_USER` / `ADMIN_PASS` | 初始管理员 | 仅首次建库生效 |
| `SEED_FEEDS` | 初始订阅源 | 仅订阅表为空时 |
| `REFRESH_MINUTES` / `KEEP_PER_FEED` / `KEEP_DAYS` | 抓取与保留 | 首次建库后请在页面改 |
| `FEED_FAIL_LIMIT` | 连续失败停用阈值（2~20） | 同上 |
| `IMG_*` | 图片缓存参数 | 同上 |
| `WATCHTOWER_HTTP_API_TOKEN` | 一键更新令牌 | 镜像模式必填 |
| `ALLOW_PRIVATE_HOSTS` | 允许服务端访问内网 | 自建 FreshRSS / 本机模型时设 `1` |
| `TRUST_PROXY` | 是否信任 `X-Forwarded-For` | 反代拓扑特殊时设 `1` / `0` |
| `PG_POOL_MAX` | 连接池上限 | 并发高时调大 |

完整说明见 `产品文档.md` 附录 B 与仓库根目录 `.env.example`。

## 17. API 小抄（脚本 / 集成用）

```bash
BASE=http://127.0.0.1:3210

# 健康检查（公开）
curl -s $BASE/api/health
# {"ok":true,"authed":false,"db":{"ready":true,"latencyMs":1}}

# 登录（字段名必须是 username / password）
curl -s -c /tmp/fl.txt -X POST $BASE/api/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin"}'

# 带会话的常用查询
curl -s -b /tmp/fl.txt $BASE/api/feeds
curl -s -b /tmp/fl.txt "$BASE/api/entries?unread=1&limit=20"
curl -s -b /tmp/fl.txt "$BASE/api/entries?q=关键词&fav=1"
curl -s -b /tmp/fl.txt "$BASE/api/entries?watch=watch"

# 新增频道
curl -s -b /tmp/fl.txt -X POST $BASE/api/feeds \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/feed.xml","groupName":"技术"}'

# 全部已读（限定频道）
curl -s -b /tmp/fl.txt -X POST $BASE/api/entries/read-all \
  -H 'Content-Type: application/json' -d '{"feeds":[1,2]}'

# 检查更新 / 一键更新（管理员）
curl -s -b /tmp/fl.txt -X POST $BASE/api/version/check
curl -s -b /tmp/fl.txt -X POST $BASE/api/update
```

**说明**

- 除健康检查、登录、登出、会话查询外都需要会话 Cookie；
- 标注管理员的接口（配置、用户、状态、图片缓存、一键更新）普通账号会 403；
- 错误响应统一 `{ "error": "...", "code": "..." }`，5xx 只给通用文案。
