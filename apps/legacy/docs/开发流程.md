## 〇、总览：两条「同步」方向

- **本地 → 远程（发版同步）**：只在发版时做一次 `git push --tags`，平时绝不推 GitHub。
- **远程 → 线上（部署同步）**：不用人为操作，`watchtower` 从 ghcr 自动拉取最新镜像重启。

日常开发全程在**本地**，不碰 GitHub、不打 tag、不占 ghcr。

### 验证登录（3211 本地测试容器）

> ⚠️ 登录接口字段是 **`username` / `password`**，不是 `user`/`pass`，写错会永远报「用户名或密码错误」。

```bash
curl -s -c /tmp/fl_cookie.txt -X POST -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin"}' http://127.0.0.1:3211/api/login
# → {"ok":true,"username":"admin","role":"admin"}

curl -s -b /tmp/fl_cookie.txt http://127.0.0.1:3211/api/version
# → {"version":"1.4.0-testN","repo":"chensnails/feedlore",...}

curl -s 127.0.0.1:3211/api/health
# → {"ok":true,"db":{"ready":true}}
```

- 3211 测试库为**全新播种**，账密即 `admin/admin`，可正常登录。
- 线上生产库（172.26.1.1）密码早改过，那台再用 `admin/admin` 会 401——不要混淆两者。

## 二、发版循环（**先确认再走**）

> ⚠️ 2026-10-27 起铁律：打 tag 前**必须先问用户确认**；开发期代码不推 GitHub，全部留本地。

| 步骤 | 动作 | 命令 / 要点 |
|---|---|---|
| 7 | **用户确认** | 发版前确认；禁止自动 push |
| 8 | 三处改正式号 + CHANGELOG | `VERSION` / `package.json.version` / `CHANGELOG.md` 三者**必须一致**；CHANGELOG 把 `[未发布]` 段落成版本段 |
| 9 | push + 打 tag | `git push origin main` → `git tag -a vX.Y.Z -m "…"` → `git push origin vX.Y.Z` |

CI `release.yml` 有 **gate**：tag 必须是三段式 `vX.Y.Z` 且与 `VERSION`/`package.json` 三者一致，否则不构建。
通过后双原生 runner（amd64 `ubuntu-24.04` / arm64 `ubuntu-24.04-arm`）构建合并 manifest 推 ghcr，打 GitHub Release。

> `-testN` / `-rc` 后缀 tag：只出镜像、不推 `latest`、不建 Release，也不会触发线上更新。

## 三、远程更新（线上服务器 172.26.1.1）

**镜像模式，唯一路线**，不要再向服务器推源码。

- **自动通道**：发版第 9 步 push + tag 后，CI 推 ghcr → `watchtower`（容器 `feedlore-watchtower`，服务名仍 `watchtower`）每 5 分钟轮询，自动拉新重启。
- **手动通道**：后台「设置 → 关于 → 一键更新」调 `/api/update`（admin），约 1~2 分钟生效。
- **已废弃、别再用**：服务器 `git pull` / `git reset --hard` / `docker compose up -d --build` / 跑 `deploy.sh` / 推代码到 `/opt/1panel/.../shiyue`（已删）。线上 compose 在 `/root/feedlore`，只读 `docker-compose.release.yml`（`ghcr.io/chensnails/feedlore:latest`）。

**查线上实际版本**（镜像里没有 `VERSION` 文件）：

```bash
docker exec feedlore node -e "console.log(require('/app/package.json').version)"
```

## 四、禁止事项（踩过坑的红线）

- 开发期不 push（含 WIP，除非你要求备份）；不推 test tag 到 origin；不把 test tag 写进 `docker-compose.release.yml`。
- commit / push / 打 tag 前先确认。
- 所有 workflow 的 `runs-on` 必须 pin `ubuntu-24.04` / `ubuntu-24.04-arm`，**禁止 `ubuntu-latest`**（曾静默迁 Ubuntu 26 致 CI 测试崩）。
- `sticky`/`fixed` 元素禁用 `backdrop-filter`（滚动掉帧主因）。
- `Object.assign` 覆盖陷阱：`Object.assign(jsonPost(patch),{method:'PATCH'})` 才不被覆盖。
- Git Bash 把 `docker exec /app/...` 绝对路径转 Windows 路径，需 `MSYS_NO_PATHCONV=1`；脚本里 `/tmp/x` 落成 `D:/tmp`，用 `os.tmpdir()`。
