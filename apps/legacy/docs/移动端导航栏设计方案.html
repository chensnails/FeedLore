笺川 FeedLore · 移动端导航栏设计方案

现状：全局导航只有 3 个目的地（文章 / 卡片 / 日报）+ 3 个操作（刷新 / 主题 / 设置），且全部堆叠在顶部两行，移动端首屏被挤压。以下提供 4 种改造方案，点击右上角切换明暗预览。
示意基于 375×812 逻辑像素（iPhone 基准），因 CSS 变量驱动，浅色/深色共用一套令牌，随应用主题自动适配。

全局 3 视图下沉到底部固定栏，顶部收为极简标题条。

适用场景内容/阅读型主 App（推荐）想最小改动、保品牌工具/现代感、内容留白多多级导航/功能密集

推荐方案：A（底部三 Tab）为基线，叠加 C 的悬浮质感作为视觉升级选项

首选落地方案 A：FeedLore 是典型「内容消费型」应用，全局只有 3 个平级目的地，底部标签栏是行业验证最稳的范式——拇指可达、首屏释放最彻底、选定态清晰，且与现有「视图级频道栏」互不冲突（频道栏继续作为视图内次级工具栏存在）。

若你希望视觉更「高级」一点，可在 A 的骨架上采用 C 的悬浮胶囊外观（圆角 + elevation + 选中软底），但保留「满宽/贴底」而非真正悬浮，避免遮挡内容、省去滚动隐藏逻辑——即「A 的结构 + C 的皮」。

  • 不推荐 B 作为最终态：它改动最小、风险最低，适合做「过渡期快速验证」，但顶部栏仍占用首屏，未根治原问题。
  • D 暂不必要：当前仅 3 个目的地，抽屉属于过度设计；可预留扩展位（若日后加入收藏/标签/关于/账户，再演进为 D）。
  • 深色模式：四方案均用 CSS 变量令牌，随应用 `auto/light/dark/github` 自动适配，无需额外工作。
  • 安全区：A/C 底部、D 抽屉均接入 `env(safe-area-inset-*)`，与现有移动端下拉组件一致。
示意图为设计稿，非最终像素；实际开发复用 FeedLore 既有 --accent / 图标雪碧图(#i-*) / 主题变量，保证与全站一致。
