## 2. 关键决策记录

### D-01｜前后端不引框架，只借 React 渲染

- **决策**：后端用 Node 22 原生 `http` + `pg` 直连，不引 Express / ORM；前端核心逻辑（状态、请求、事件）用原生 JS 单例，只有视图层用 React。
- **理由**：部署面小（单容器、依赖少）、升级不易被上游破坏；核心逻辑可以脱离 React 测试。
- **代价**：路由、参数解析、错误映射都要自己写 —— 1.7.2 的 S-05（错误码收敛）就是在补这笔账。
- **约束**：`src/core/` 必须严格单向依赖（`util → state → feeds → reader → autorefresh → ui → bootstrap → index`），副作用只放 bootstrap。

### D-02｜断点只保留两档语义（720 导航 / 820 密度）

- **背景**：早期 `1080` 承担「侧栏 → 抽屉」的降级，JS 侧却以 720 判定。
- **后果**：721–1080px 窗口下 CSS 已把侧栏 translate 出屏（实测 `x = -270`），而 state 仍认为侧栏常驻 → 「关注 / 屏蔽」在 DOM 里但不在视口内，用户看到的是「点不动」。
- **决策**：导航降级统一到 **720**，与 `src/core/reader.js` 阈值对齐；721px 以上恒常驻侧栏。
- **铁律**：改 CSS 断点必须同步改 JS 阈值，否则立刻重现同一类 bug。

### D-03｜移除阅读器式快捷键（1.7.1）

- **决策**：删掉 `j/k/o/s/u/?` 与 `/`，只保留 `⌘K` 命令面板。
- **理由**：实际使用率低、与中文输入法冲突、维护成本高（每加一个功能都要考虑键盘路径）。
- **例外**：`⌘K` 保留 —— 命令面板没有其它入口，删了会变成死功能。

### D-04｜移除顶部标签栏与卡面标签（1.6.0-test2）

- **决策**：`TagBar` 整体下线，卡面 / 列表项不再显示标签；**正文内的标签保留**。
- **理由**：标签在卡片上是噪音，且与搜索、分组的功能重叠；顶栏空间要留给搜索与视图切换。

### D-05｜自动加载改用 document 捕获监听（1.6.0-test5）

- **背景**：App Shell 后列表在各自滚动容器里滚，而两页的自动加载仍监听 `window` 的 `scroll` —— 事件永远不来。
- **决策**：改为 document 捕获监听（`scroll` 不冒泡但能被捕获）+ 滚动哨兵 `getBoundingClientRect`；同时**移除卡片页「加载更多」按钮**。
- **理由**：一处收齐所有滚动容器，不用为每个容器单独绑定。

### D-06｜所有出网口收敛到 `lib/net.js`（1.7.2）

- **背景**：安全测试发现订阅地址 / Webhook / 模型 BaseURL 三处只校验协议不校验主机，`http://169.254.169.254/latest/meta-data/` 311ms 就能拿到响应。
- **决策**：`assertPublicHost()`（字面量内网 + DNS 解析后判 A/AAAA）+ `safeFetch()`（已校验 IP 经 undici `connect.lookup` 钉定、`redirect:'manual'` 逐跳校验 ≤3 跳）。
- **逃生口**：`ALLOW_PRIVATE_HOSTS=1`（自建 FreshRSS / 本机 Ollama）。
- **铁律**：以后任何「服务端替用户访问地址」的功能，都必须走这两个函数。

### D-07｜错误响应只认 `classifyError()`

- **决策**：PG SQLSTATE 22/23 → 400「请求参数不合法」；连接类 → 503；其余 → 500 通用文案。5xx 绝不回吐 `err.message`。
- **理由**：原来统一 502 且把 PG 原文直接返回（`invalid byte sequence... 0x00`、`getaddrinfo ENOTFOUND db`），既是信息泄露也让监控无法区分「参数错」和「依赖挂了」。

### D-08｜测试桩不能比生产多字段（1.7.3 教训）

- **背景**：1.7.2 的渲染隔离让折叠集合 `useMemo` 依赖 `state.rdCollapsedGroups`，但 `state` 上从没有这个字段（只在 `layoutPref` 里），key 恒为 `"[]"` → 折叠冻结。377 项回归全绿，因为**测试桩自己造了这个字段**。
- **决策**：新增 `LAYOUT_MIRROR = ['sort','rdScope','rdCollapsedGroups']`，`setLayout()` 写偏好后统一回填 `state`；补一条**静态**用例（查源码断言字段声明、镜像表登记、初值来源）。
- **铁律**：React 里读 `state.x` 前必须确认 core 真在 `state` 上写了它；同类偏好新增时登记进 `LAYOUT_MIRROR`。

### D-09｜预发布 tag 不推 `latest`、不建 Release

- **决策**：`release.yml` 的 `gate` 按 tag 形态分三档 —— `vX.Y.Z` 全流程；带 `-suffix` 只出镜像；其它不构建。三档都要求与 `VERSION`、`package.json` 三者一致。
- **理由**：Watchtower 只看 `latest`，预发布不能污染线上；同时避免「main 有新提交 = 有新版本」的误解。

### D-10｜静态资源必须带内容哈希

- **背景**：旧 `public/style.css` 固定名被 CDN 缓存 1~4 小时，而 `index.html` 是 no-cache → 新 HTML/JS + 旧 CSS 错配（1.4.0 搜索框 svg 撑爆）。
- **决策**：`src/style.css` / `src/login.css` 走 Vite 出 `assets/*-<hash>.*`；带哈希资源 `immutable`，无哈希 `no-cache`；新增静态资源一律进 `src/` 走打包，**不得放回 `public/` 固定名**。

## 3. 踩坑清单（按领域，复用价值最高）

### 3.1 CSS / 布局

| 坑 | 现象 | 正解 |
|---|---|---|
| 断点语义错位 | 元素在 DOM 里但点不到 | CSS 断点与 JS 阈值必须一致（见 D-02） |
| `flex: 1 1 auto` 撑爆换行 | 长频道名把顶栏挤成两行（44 → 88px） | 基准改 `0`（`flex:1 1 0`），靠 `min-width` 兜底 |
| flex 子项缺 `min-width:0` | 列表容器被内容撑到 1600px，超出部分被裁 | 容器与行都补 `min-width:0` |
| `sticky` / `fixed` 上用 `backdrop-filter` | 滚动掉帧 | 毛玻璃只用于静态或已锁滚动的弹层 |
| 动效令牌自引用 | `--dur-fast: var(--dur-fast)` → 全站 transition 时长回落 0s | 改为具体值，禁止循环引用 |
| 6 个 `@media(max-width:720px)` 段被合并 | 实测 181 处样式偏差 | 层叠依赖源码顺序，**不许合并** |
| sprite 图标漏基础类 | svg 撑爆 / 路径填黑 | 新图标必须进 `.ico` 基础组（含 `fill:none; stroke:currentColor`） |

### 3.2 React

| 坑 | 现象 | 正解 |
|---|---|---|
| memo key 指向不存在的 state 字段 | 数据变了但界面不动（1.7.3 回归） | 先确认字段真在 state 上；或用镜像表统一回填 |
| 测试桩造了生产没有的字段 | 回归全绿但线上坏 | 静态用例查源码 |
| 管理员标记用一次性 `useState` | 刷新后权限入口时有时无 | 走 `applyRoleUI()` → 宿主桥 `setAdminFlag` |
| 受控输入测试 | CDP 设 `el.value` 不触发 React | 用 `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set` 再派发 `input` |
| 卡片 → 文章跳转竞态 | 提示「找不到该文章」 | `jumpToFeed` 在 `switchView('reader')` **前**落筛选条件；`focusReaderArt` 先等 `rdLoading` 落地 |

### 3.3 Node / 服务端

| 坑 | 现象 | 正解 |
|---|---|---|
| `decodeURIComponent` 裸调用 | 一个畸形 Cookie 打挂进程（S-01） | 解析容错 + 会话解析移进 `try` + 进程级兜底 |
| 内网判定拦 `198.18.0.0/15` | Clash / Surge fake-ip 把域名解析成 198.18.x.x → 46 个订阅集体抓取失败 | **禁拦**这一段 |
| 「凡 IPv6 一律拒」 | 公网 AAAA（example.com）被误杀 | 按前缀判 `::1` / `fe80::/10` / `fc00::/7` / `ff00::/8` / IPv4-mapped |
| 登录限流按 socket IP | 反代后全站共用一个桶，一个人锁死所有人 | 键改「真实 IP + 用户名」+ 指数退避 |
| `db.ready` 只置 true 不复位 | 停库后 health 仍 200（谎报） | 真实 `SELECT 1` 探活 + 超时 |
| 限流表无上限 | 海量 IP 撑爆内存 | 加容量上限与清扫 |
| `new URL(req.url)` 放在 try 外 | 畸形 URL 同样能打挂进程 | 所有可能抛的解析都留在 try 内 |
| IP 钉定 lookup 只写 `cb(null, ip, family)` | undici 带 `{ all: true }` 解析 → `ERR_INVALID_IP_ADDRESS` → 全站抓取失败（1.7.4） | 三形态都兜：`{all:true}` 回**数组**，另加两参 `(host, cb)` |
| `undici` 依赖与 Node 内置跨大版本 | `dispatcher` 抛 `invalid onRequestStart method`，连连接都不建立 | 精确锁同大版本（现 `6.29.1`），启动时自检告警 |
| 出网改动只靠 `lookup` 桩测安全性 | 125 项全绿，线上一个频道都没抓成（1.7.2~1.7.3） | 改完必须容器内实跑一次真实抓取 |

### 3.4 部署 / CI

| 坑 | 现象 | 正解 |
|---|---|---|
| `runs-on: ubuntu-latest` | 静默迁到 Ubuntu 26，CI 崩 | 必须 pin `ubuntu-24.04` / `ubuntu-24.04-arm` |
| 镜像里没有 `VERSION` 文件 | 查不到版本 | `docker exec feedlore node -e "console.log(require('/app/package.json').version)"` |
| 只 `docker cp dist` 更新本地容器 | 「关于」页版本不变（版本来自镜像内 `package.json`） | 必须重建镜像再 `compose up -d` |
| Watchtower 未开 API | 一键更新 404 | `WATCHTOWER_HTTP_API_UPDATE=true`；Docker 29+ 需 `DOCKER_API_VERSION=1.44` |
| 本地代理已死 | git 网络命令 EOF | 统一带 `-c http.proxy= -c https.proxy=` |
| Docker Desktop `wslrelay` 抢占 3211 | 宿主机 curl 全部超时，容器内部正常 | `taskkill /F /PID <wslrelay pid>` |
| Git Bash 路径转换 | `/app/...` 被转成 Windows 路径 | `MSYS_NO_PATHCONV=1` |

### 4.1 修掉的（1.7.2）

| 编号 | 严重度 | 问题 | 修法 |
|---|---|---|---|
| S-01 | **P0** | 畸形 Cookie → `URIError` → 进程退出，未授权单请求即可打挂 | 解析容错 + 移进 try + 进程级兜底 |

| S-06 | P2 | Webhook 可指向内网 | 保存与发送双重校验 |
| S-03 | P2 | 登录限流全站共享 | IP + 用户名双维度 + 指数退避 |
| S-04 | P2 | 健康检查谎报 | 真实探活，库挂返回 503 |
| S-05 | P2 | 错误统一 502 且回吐 PG 原文 | `HttpError` + `classifyError` |
| S-07 | P2 | 无安全响应头 | CSP / nosniff / XFO / Referrer / Permissions / COOP / HSTS |

### 4.2 留待 1.8.0

| 编号 | 问题 |
|---|---|
| S-08 | 超大 body 直接 `req.destroy()`，没有 413 |
| S-09 | 部分接口参数数量与脏值校验不全 |
| S-10 | 密码最短 4 位，策略过弱 |
| S-11 | 日报 / 测模型等烧钱接口无频控 |
| S-12 | `/api/users` N+1 查询 |

### 4.3 守得住的部分（实测确认）

- SQL 全参数化：`q=' OR 1=1--`、`tag='); DROP TABLE entries;--` 均无效，表数据完好；
- 跨账号越权全部 404（读条目 / 改标记 / 改频道 / 删频道）；
- 路径穿越 6 种写法（含双重编码）全 404；
- 正文走纯文本渲染，全仓仅 1 处 `innerHTML` 且已 `escapeHtml`；
- 会话 HMAC + `timingSafeEqual`，Cookie `HttpOnly` + `SameSite=Lax`；
- 性能：1 万条下 entries p95 32ms、flags 11ms、feeds 22ms、20 并发 179ms。
