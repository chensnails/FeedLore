## 1. 产品定位

**一句话**：把「订阅 → 阅读 → 沉淀」收在一个自托管服务里的 RSS 阅读器，附带资源卡片墙与按账号配置的 AI 日报。

**目标用户**

- 有自己服务器（或 NAS）的个人用户，习惯用 RSS 管信息源；
- 三五人的小圈子 / 团队，想共享一套服务但各自订阅互不干扰；
- 在意「订阅列表、已读记录、阅读偏好不落在第三方手里」的人。

**要解决的问题**

| 痛点 | 做法 |
|---|---|
| 信息散在几十个站点与公众号，逐个打开太慢 | 频道 + 分组统一收口，一屏读完 |
| 平台推荐算法决定你看到什么 | 只有订阅，没有推荐；顺序由时间与你自己设的规则决定 |
| 读到一半跳走就找不回来 | 已读 / 未读 / 收藏三态，服务端搜索覆盖正文 |
| 值得留的资源混在文章流里被冲走 | 卡片墙独立成视图，网格 / 列表两种密度 |
| 想要「今天有什么值得看」的摘要，又不想把 Key 交给别人 | 日报按账号绑定模型，Key 加密落库、页面只显示掩码 |
| 第三方阅读器要付费、要账号、会停服 | 单容器自托管，数据在自己的 PostgreSQL 里 |

**明确不做**

- 不做开放注册（账号只由管理员创建）；
- 不做推荐算法、热度榜、社交关注；
- 不做埋点、广告、第三方统计（全站无外链脚本）；
- 不做多租户 SaaS 计费，不做「云端版」。

## 2. 术语表

| 术语 | 对应英文 / 字段 | 含义 |
|---|---|---|
| 频道 | feed | 一个 RSS / Atom 订阅源 |
| 分组 | group（`feeds.group_name`） | 频道的归类，可折叠、可拖拽排序 |
| 条目 | entry | 一篇文章（标题、摘要、正文、图片、链接） |
| 卡片 | card | 卡片墙中对条目的展示形态，与条目是同一份数据 |
| 范围 | scope | 文章页的三种基础筛选：全部 / 未读 / 收藏 |
| 虚拟视图 | watch | 「关注」「屏蔽」两个跨频道聚合视图，由规则产出 |
| 关注 / 屏蔽规则 | `prefs.watchRules` | 关键词规则，抓取入库时给条目打标 |
| 条目过滤 | `prefs.filters` | 只收 / 屏蔽规则，在**入库前**逐人拦截 |
| 日报 | digest | 由大模型基于过去 24 小时条目生成的简报 |
| 视图 | view | 三个主视图：文章（reader）/ 卡片（cards）/ 日报（ai） |
| 单篇 / 多篇 | accordion | 手风琴模式：展开一篇是否自动收起上一篇 |

> **关注/屏蔽规则** 与 **条目过滤** 是两套东西：前者「打标 + 聚合查看」，条目仍留在原频道；后者「根本不让它进库」，二者互不影响。

## 3. 功能全景

### 3.1 阅读（文章视图）

| 能力 | 说明 |
|---|---|
| 范围切换 | 全部 / 未读 / 收藏；可与「关注 / 屏蔽」叠加 |
| 频道栏 | 品牌区 + 频道搜索 + 范围行（全部 / 未读 / 收藏 / 关注）+ 分组与频道 + 底部「屏蔽」+ 添加频道；分组可折叠、栏宽可拖拽（双击恢复默认） |
| 就地读全文 | 点标题展开正文，再点收起；单篇 / 多篇两种手风琴模式 |
| 图文原样 | 图片按原文顺序内联，统一走服务端代理，源站防盗链不裂图 |
| 标记 | 单条已读 / 未读、收藏（左侧主色竖条 + 星标变色） |
| 批量 | 「全部已读」作用于当前筛选结果；「全部收起」收起所有展开项 |
| 搜索 | 服务端检索，覆盖标题 / 摘要 / 正文 / 标签；可与频道、范围叠加 |
| 自动加载 | 滚动到底自动续拉，无需点「加载更多」 |
| 自动刷新 | 站点级开关（设置 → 数据源 → 采集参数），按间隔重新读取列表，不额外触发服务端抓取 |
| 条目深链 | 地址栏记录 `#reader/art/<id>`，刷新可回到那一条并置顶 |
| 快捷键 | 仅保留 `⌘K / Ctrl+K` 呼出命令面板（其余键盘快捷键已在 1.7.1 移除） |

### 3.2 订阅管理（设置 → 数据源）

| 能力 | 说明 |
|---|---|
| 新增频道 | 粘贴 RSS / Atom 地址，保存时立即试抓一次 |
| OPML 导入 | 保留分组；文件内去重 + 与现有库去重，回包报告新增 / 重复 |
| OPML 导出 | 页面按钮或命令面板，导出 `feedlore-subscriptions-日期.opml` |
| 频道编辑 | 重命名、**改订阅地址**、改分组、设单独抓取频率 |
| 双开关 | 「采集」控制是否定时抓取；「卡片」控制是否进卡片墙 |
| 排序 | 拖拽（组内 / 跨组）或填序号，两种方式并存 |
| 删除 | 单频道删除，连带其条目 |
| 失败处理 | 连续失败达阈值自动停用并标注「抓取失败」，重试成功自动恢复 |

### 3.3 卡片墙（卡片视图）

| 能力 | 说明 |
|---|---|
| 网格 / 列表 | 两种密度，⋮ 菜单切换 |
| 排序 | 最新 / 最早 / 名称 |
| 筛选 | 频道下拉（含「全部频道」）+ 关键词搜索 |
| 详情弹窗 | 点卡片弹出全文，含「收藏」「在文章页查看」「打开原文」「复制链接」 |
| 跨视图跳转 | 「在文章页查看」切到文章页、滚到该条并短暂描边高亮 |
| 无限滚动 | 滚动到底续拉；一屏未满时自动续拉 |

### 3.4 关注 / 屏蔽（设置 → 规则）

| 能力 | 说明 |
|---|---|
| 规则 | 每条规则 = 名称 + 关注/屏蔽 + 多行关键词 + 是否推送 + 是否启用 |
| 匹配 | 子串匹配、不区分大小写；同时命中关注与屏蔽时**按屏蔽处理** |
| 打标 | 抓取入库后对新条目判定，写 `entries.watch_state` / `watch_rule`；屏蔽命中顺手置已读 |
| 聚合视图 | 频道栏「关注」「屏蔽」两个虚拟视图，可再点一次退出 |
| Webhook | 一条全局地址；每条关注规则单独决定是否推送，同轮命中合并成一条消息 |
| 回溯 | 「应用到已有文章」按游标分批判定存量条目 |

### 3.5 条目过滤（设置 → 账号 → 条目过滤规则）

| 项 | 说明 |
|---|---|
| 动作 | **屏蔽**（命中即丢弃）/ **只收**（仅保留命中的，白名单） |
| 匹配范围 | 标题 / 摘要 / 正文 / 全部（= 标题 + 摘要 + 正文） |
| 匹配方式 | 关键词（不区分大小写）/ 正则（非法正则在保存时被丢弃） |
| 数量限制 | ≤ 50 条，单条 ≤ 200 字 |
| 执行顺序 | 两者同存时**先按屏蔽拉黑，再按只收拉白** |
| 生效范围 | 在写库**之前**过滤，只影响之后新抓的条目，已入库文章不动 |
| 隔离 | 每个账号独立配置，互不影响 |

### 3.6 外观

主题 4 套（跟随系统 / 浅色 / CommaFeed 暗色 / GitHub 暗黑）、主色 6 套、界面字号 3 档、卡片密度 2 档、正文字体 2 种、正文行高 3 档、正文字号 3 档、阅读宽度 4 档。全部即时生效并按账号保存。

### 3.7 AI 日报

- 模型按账号绑定（地址 / Key / 模型名），Key 落库前 AES-256-GCM 加密，回显只给掩码；
- 可设自动生成时间（北京时间）、摘要范围（仅采集开启的频道 / 全部 / 自定义）、每频道条数上限（默认 20）、总量上限（默认 150）、保留天数（默认 30）、自定义写作风格；
- 支持手动生成与「重新生成（忽略缓存）」、「测试连通」；
- 不配 Key 不影响任何其它功能。

### 3.8 多用户与角色

- 账号由管理员创建，无开放注册；
- 订阅源、条目、已读、收藏、外观、规则、模型、日报全部按账号隔离；
- 同一 URL 被不同账号订阅互不影响（各自独立抓取记录与条目副本）。

### 3.9 移动端（PWA）

- 窄屏（≤720px）频道栏 → 抽屉，弹层整屏推入、支持下拉手势关闭；
- HTTPS 下「添加到主屏幕」即可安装，外壳与静态资源走 Service Worker 缓存；`/api` 一律网络优先、不缓存数据。

### 3.10 更新通道

- 「设置 → 关于」显示当前版本，可检查 GitHub 最新 Release（缓存 10 分钟）；
- 镜像 + Watchtower 模式下，管理员可「一键更新」：后端转发 Watchtower 触发拉镜像重启，页面轮询版本号直到变化。

### 3.11 命令面板

`⌘K / Ctrl+K` 呼出，支持中文拼音首字母检索。命令分六组：视图切换、主题、设置分区、阅读范围、操作（刷新 / 聚焦搜索 / 回到顶部 / 导出 OPML）、跳转到频道。

## 6. 关键业务规则

### 6.1 抓取调度

| 项 | 默认 | 范围 |
|---|---|---|
| 全局抓取间隔 `refreshMinutes` | 30 分钟 | 5 ~ 1440 |
| 单频道间隔 | 跟随全局 | 同上，按频道覆盖 |
| 每频道保留条数 `keepPerFeed` | 300 | 20 ~ 5000 |
| 最长保留天数 `keepDays` | 0（不限） | 0 ~ 1095 |
| 抓取超时 | 按配置 | — |
| 抓取并发 `concurrency` | 3 | — |
| 连续失败自动停用 `feedFailLimit` | 5 | 2 ~ 20 |

- 使用 ETag / Last-Modified 做条件请求，未变更不重复解析；
- `fail_streak` 达阈值 → 频道自动停用（`enabled=false` 并记录原因），之后任一次抓取成功自动恢复；
- 抓取走统一出网层：先做地址校验，再发请求（见 6.8）。

### 6.2 去重与保留

- 频道按规范化 URL 去重，同一账号不会重复订阅同一地址；
- 条目按 guid / link 去重，重复抓取不产生副本；
- 保留策略双约束：先按条数截断，再按天数清理（`keepDays=0` 时只按条数）。

### 6.3 关注 / 屏蔽

- 规则上限 30 条；每条关键字 ≤ 50 个、单个 ≤ 60 字；
- 子串匹配、不区分大小写，不做正则（避免性能与误伤）；
- 关注与屏蔽同时命中 → 屏蔽优先；
- 屏蔽命中时条目会被置为已读，避免占用未读；
- 打标只加字段，不复制条目，原频道与聚合视图看到的是同一条。

### 6.4 日报

- 时间窗口：过去 24 小时；
- 自动生成到点执行，**错过不补**，第二天照常；
- 生成结果按账号 + 日期缓存，同日重复请求返回缓存，除非显式「重新生成」；
- 日报的模型调用同样走出网校验，禁止指向内网（除非开 `ALLOW_PRIVATE_HOSTS`）。

### 6.5 图片

- 统一 `/api/img` 代理，L1 内存 + L2 数据库 + SWR（过期先回旧图、后台静默刷新）；
- 默认参数：回源窗口 7 天、库内保留 90 天、最长边 1280px、WebP 质量 78；
- 按图片 URL 哈希去重存储，避免同一张图重复落库。

### 6.6 搜索

服务端检索，参数可组合：

| 参数 | 作用 |
|---|---|
| `q` | 关键词（覆盖标题 / 摘要 / 正文 / 标签） |
| `feed` | 限定频道 |
| `tag` | 限定标签 |
| `unread=1` | 只看未读 |
| `fav=1` | 只看收藏 |
| `watch=watch\|block` | 关注 / 屏蔽聚合 |

### 6.7 会话与加密

- 密码：`scrypt`（64 字节）+ 每用户独立盐；
- 会话：`base64url(JSON{uid,u,exp}) + "." + HMAC-SHA256`，Cookie `feedlore_sid`，`HttpOnly` + `SameSite=Lax`，有效期 7 天；
- 模型 Key：AES-256-GCM，主密钥由 `cryptoSecret` 经 scrypt 派生，格式 `enc.v1.<iv>.<tag>.<密文>`；
- 加密边界要说清楚：`cryptoSecret` 本身也在库里，所以它防的是「备份 / 日志 / 截图 / 误导出被拖走」，**不是**防「拿到整库的人」。

### 6.8 安全基线（1.7.2 起）

| 项 | 做法 |
|---|---|
| 出网校验（防 SSRF） | 所有「服务端替用户访问地址」的入口（订阅抓取、Webhook、模型 BaseURL）都过 `assertPublicHost()` + `safeFetch()`：先判字面量，再按 DNS 解析出的 A/AAAA 判 IP，建连时把 IP 钉死（防 rebinding），重定向逐跳重新校验（≤3 跳） |
| 内网放行 | 自建 FreshRSS / 本机 Ollama 等场景，显式设 `ALLOW_PRIVATE_HOSTS=1` |
| 登录限流 | 键为「真实 IP + 用户名」，指数退避 60s → 2min → … 上限 15min；反代下取 XFF 最后一段（仅直连方是内网/回环才信任） |
| 错误响应 | 统一 `classifyError()`：参数类 4xx、依赖故障 503、其余 500 只回通用文案；5xx 绝不回吐数据库原文 |
| 健康检查 | `SELECT 1` 真实探活，库不可用返回 **503** |
| 安全响应头 | CSP、nosniff、X-Frame-Options、Referrer-Policy、Permissions-Policy、COOP；HTTPS 追加 HSTS |
| 崩溃兜底 | 进程级 `uncaughtException` / `unhandledRejection` 记日志不退出；Cookie 解析容错 |

> 上述均是「改错一行就重返漏洞」的位置，已钉成服务端单测（见 `tests/server/unit.test.js`）。

## 7. 非功能特性

### 7.1 性能（本地容器实测，1 万条条目 / 46 频道）

| 指标 | 结果 |
|---|---|
| `GET /api/entries`（分页 30）p95 | 32 ms |
| `GET /api/entries/flags` | 11 ms |
| `GET /api/feeds`（46 频道） | 22 ms |
| 20 并发混合请求总耗时 | 179 ms |
| 首屏静态资源（gzip 合计） | 约 150 KB |

结论：在万级条目规模下，服务端不是瓶颈；交互流畅度主要取决于前端渲染策略（频道栏已做 memo 隔离与延迟过滤）。

### 7.2 兼容性

| 维度 | 支持范围 |
|---|---|
| 浏览器 | Chromium 内核（Chrome / Edge）、Safari、Firefox 近两年版本 |
| 屏幕 | 桌面 ≥ 721px 常驻侧栏；≤ 720px 抽屉模式；≤ 480px 顶栏进一步收成图标 |
| 部署架构 | 单容器，镜像同时出 amd64 / arm64 |
| 数据库 | PostgreSQL 18（compose 内自带 `postgres:18-alpine`） |
| 运行时 | Node 22 |

### 7.3 可观测性

- `/api/health`：`{ ok, authed, db: { ready, latencyMs } }` —— 真实探活，可直接给 Docker HEALTHCHECK 与外部监控用；
- 「设置 → 状态」：运行时长、条目 / 频道 / 用户计数、数据库体积、上次抓取结果（新增 / 失败 / 耗时）、失败频道清单、日报状态、诊断信息一键复制；
- 服务端日志只输出关键事件与错误堆栈，不打印正文与凭据。

## 8. 技术架构

### 8.1 组成

```
浏览器（React 19 + Vite MPA）
   │  fetch /api/*
   ▼
Node 22 原生 http（server.js，无框架）
   ├── 会话 / 鉴权 / 限流 / 安全头        lib/http.js
   ├── 出网校验与安全抓取                 lib/net.js
   ├── RSS/Atom 抓取与解析                rss.js
   ├── 条目过滤 / 关注屏蔽规则            lib/filter.js · lib/watch.js
   ├── AI 日报生成                        digest.js
   ├── 图片代理与缓存                     server.js（/api/img）
   └── 数据访问                           db.js（pg 直连，无 ORM）
                                            │
                                            ▼
                                   PostgreSQL 18
```

### 8.2 前端结构

- **MPA 双入口**：`index.html`（应用）+ `login.html`（登录）；Vite 构建后静态资源带内容哈希。
- **核心单例 `src/core/`**：`util → state → feeds → reader → autorefresh → ui → bootstrap → index`，严格单向依赖。核心持 state、发请求、派发窗口事件；视图只渲染，控件经 `core.*` 改 state。
- **渲染驱动**：`__cardsTick` / `__readerTick` / `__shellTick` / `__overlaysTick` / `__viewChanged` / `__appearanceChanged`。
- **App Shell**：`body{overflow:hidden}`，三视图各自独立滚动，各视图自带吸顶工具条（不再有全局顶栏）。

### 8.3 数据模型

| 表 | 作用 | 关键字段 |
|---|---|---|
| `users` | 账号与偏好 | `username` / `password_hash` / `salt` / `role` / `prefs`(JSONB) |
| `feeds` | 频道 | `owner_id` / `url` / `title` / `group_name` / `sort_order` / `enabled` / `fail_streak` |
| `entries` | 条目 | `feed_id` / `guid` / `title` / `content` / `published_at` / `read_at` / `favorite` / `watch_state` |
| `digests` | 日报 | `owner_id` / `date` / `content` / `stats` |
| `image_cache` | 图片缓存 | `url_hash` / `mime` / `bytes` / `fetched_at` |
| `settings` | 站点设置 | `key` / `value`(JSONB)：采集参数、图片参数、会话密钥等 |

> 偏好（外观 / 规则 / 模型 / 日报 / 过滤）统一存 `users.prefs`，服务端有白名单清洗，前端只拿得到清洗后的结构。

### 8.4 构建与交付

- 多阶段 Dockerfile：builder 阶段装依赖并打包前端，运行阶段用 `node:22-bookworm-slim`，只带运行所需文件，并带 `HEALTHCHECK`（30s 间隔、5s 超时、3 次重试）；
- 两个 compose：`docker-compose.yml`（源码构建）、`docker-compose.release.yml`（ghcr 镜像 + Watchtower）；容器名、数据库卷、网络完全一致，可互切且数据零迁移；
- CI：push tag 触发 `release.yml`，`gate` 校验 tag 与版本号三段式一致后，双原生 runner（amd64 / arm64）构建并合并 manifest 推 ghcr。

## 10. 已知限制与产品边界

| 限制 | 说明 | 影响 |
|---|---|---|
| 无开放注册 | 账号只能管理员创建 | 不适合公开运营 |
| 无全文抓取（Readability） | 只展示订阅源给出的 `content` / `description` | 摘要型源读不到全文 |
| 关注 / 屏蔽不支持正则 | 刻意限制为子串匹配 | 复杂匹配需靠条目过滤或外部工具 |
| 日报依赖外部模型 | 需自备地址与 Key | 不配则无日报，其它功能不受影响 |
| 日报为「当日一次性生成」 | 错过时间不补 | 需要补可在页面手动生成 |
| 无 OPML 定时同步 | 只能手动导入导出 | 多端迁移需手工 |
| 搜索为子串匹配 | 未接分词 / 向量检索 | 中文同义词召回有限 |
| 单实例部署 | 未做多副本共享队列 | 抓取任务不跨实例协调 |
| 移动端为 PWA | 无原生 App | iOS 上后台刷新能力受限 |
