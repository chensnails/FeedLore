# FeedLore 前端 UI 审查报告（2026-10-28）

> 审查日期：2026-10-28
> 审查对象：笺川（FeedLore）当前前端（v1.5.1 同构前端）
> 审查方式：**只读代码审查 + 真实浏览器实机量化**（Edge headless + CDP），**未修改任何应用代码**
> 环境：Edge 156.0.4314.42；本地容器 `feedlore-test`（3211，镜像版本 1.5.0-test1）
> 说明：1.5.1 的改动全部落在 `db.js` / `lib/` / `server.js` / 测试，**未触碰 `src/style.css` 与 `src/views/*.jsx`**，故前端与 1.5.1 完全同构，本报告结论对 1.5.1 成立。
> 关系：本文件为独立新报告；`docs/UI审查报告.md`（v1.1.12 历史报告）原样保留。

---

## 0. 结论摘要

- **最高优先级（P1）**：`src/style.css:98-100` 的动效时长令牌 `--dur-fast/--dur-base/--dur-med` 是 `var(--dur-xxx)` **自我引用**（CSS 循环依赖），解析为「保证无效值」→ 全站 60+ 处 `transition`/`animation` 整条失效，时长回落 `0s`，所有微交互**瞬时硬切**。实机实测 `.btn` 的 `transition-duration = 0s`、`--dur-base` 解析为空，而登录页（`login.css` 局部定义 `.15s`）正常，交叉印证根因。
- **对比度：实测全部达标**（澄清误报）：浅色正文 15.15:1、次要 5.76:1、极淡 4.55:1、星标 4.50:1；深色正文 9.37:1、极淡 5.45:1。**「对比度不足」在实际渲染中不成立**，仅极淡文字处于 AA 阈值边缘（4.5~5.0），属「刚好合规」而非缺陷。
- **拟态：浅色正常、暗色偏弱**。浅色卡片阴影 `rgba(163,177,198,.55) 6px 6px 16px / rgba(255,255,255,.9) -6px -6px 16px`，层级清晰；暗色高光仅 `rgba(255,255,255,.05)`、黑阴影在暗底可见度低 → 暗色下卡片「发平、层级弱」。
- **玻璃拟态：存在越界使用**。`.modal-mask` 恒 `blur(8px)`、桌面 `.dd-panel` 恒 `blur(16px)`，而桌面下拉打开时**页面未锁定滚动**，与本文件「模糊仅用于滚动锁定层」的性能铁律冲突。
- **测试基线**：UI 回归 **355/355 通过**（jsdom 结构/静态规则断言），但**不覆盖**视觉渲染、CSS 自定义属性解析、动画、对比度、模糊——本报告用实机量化补齐了这一盲区。

## 2. 实机量化证据

### 2.1 动效令牌（P1 确认）
| 场景 | `--dur-base` 解析 | `.btn` transition-duration |
|---|---|---|
| 登录页（`login.html`） | `.15s`（`login.css:34` 局部定义） | N/A（登录页无 `.btn`） |
| 应用页（卡片/文章/设置/下拉/窄屏 全部） | **空** | **`0s`** |

结论：主应用 `style.css` 未真正定义三个时长令牌 → 引用它们的过渡/动画全部失效。登录页因另定义而正常，恰好反证根因在 `style.css`。

### 2.2 对比度（WCAG，实测）
| 组合 | 比值 | 判定 |
|---|---|---|
| 浅色 正文 `#1b1f26` on `#f4f5f7` | 15.15 | ✅ |
| 浅色 正文 on `#ffffff` | 16.53 | ✅ |
| 浅色 次要 `#57616f` on `#f4f5f7` | 5.76 | ✅ |
| 浅色 极淡 `#66717f` on `#f4f5f7` | 4.55 | ⚠️ 刚过 AA |
| 浅色 极淡 on `#ffffff` | 4.96 | ✅ |
| 浅色 星标 `#9a6608` on `#f4f5f7` | 4.50 | ⚠️ 阈值 |
| 浅色 主色文字 `#1c53d1` on `#f4f5f7` | 6.00 | ✅ |
| 深色 正文 `#c9c9c9` on `#242424` | 9.37 | ✅ |
| 深色 正文 on `#2e2e2e` | 8.20 | ✅ |
| 深色 次要 `#a6a6a6` on `#242424` | 6.38 | ✅ |
| 深色 极淡 `#999999` on `#242424` | 5.45 | ✅ |

结论：**无对比度违规**；仅极淡/星标处于 4.5 阈值附近，建议作为「守住不再下调」的边界，而非当前缺陷。

### 2.3 拟态阴影实测
| 主题 | `.card` box-shadow（实测） |
|---|---|
| 浅色 | `rgba(163,177,198,.55) 6px 6px 16px, rgba(255,255,255,.9) -6px -6px 16px` |
| 暗色 | `rgba(0,0,0,.55) 6px 6px 16px, rgba(255,255,255,.05) -6px -6px 16px` |

判断：浅色浮起感正常、阴影柔和（16px blur，不生硬）；暗色高光过弱（.05）+ 黑阴影贴着暗底 → **层级偏弱、卡片发平**。

### 2.4 玻璃模糊实测
| 元素 | backdrop-filter | 备注 |
|---|---|---|
| `.modal-mask` | `blur(8px)` | 弹层遮罩（页面已锁滚动，合规） |
| `.modal` | `blur(var(--glass-blur))=16px` | 与遮罩叠加 → **双重模糊** |
| `.dd-panel`（桌面） | `blur(16px)` | **页面未锁滚动即模糊**，违反性能铁律 |
| `.link-menu` | `blur(var(--glass-blur))` | 悬浮小弹层，同样未锁滚动 |

## 4. 视觉观察（来自实机截图）

- **浅色拟态**：卡片柔和浮起、层级清晰，观感良好。
- **暗色拟态**：卡片 `#2e2e2e` on `#242424`，高光 `.05` 过弱 → 卡片「发平、层级模糊」。这是「层级模糊」观感的**唯一成立场景**（暗色），需针对性增强。
- **360 窄屏**：工具栏单行不折行（≤360 已隐藏文字标题），未见折行翻倍；P2-4 属 361–374 边缘风险。
- **设置弹窗**：背景模糊自然，无穿透异常；双重模糊仅冗余不显眼。
- **无图卡片**：留白失衡（P3-11）。
- **同图同标题条目并排重复**（出现两张完全相同的卡片）：属内容层重复（移除图片去重后不再有读取端过滤），观感上像重复渲染，建议由采集层去重或接受，非 UI 缺陷，低优先。

## 5. 结构化优化建议（按主题）

| 主题 | 建议 | 对应缺陷 | 预期收益 |
|---|---|---|---|
| 动效令牌 | `style.css:98-100` 三行改为具体值（`--dur-fast:.12s` / `--dur-base:.15s` / `--dur-med:.18s`）；新增守门断言「任何 `--dur-*` 不得自引用」 | P1-1 | 3 行改动恢复全站过渡/动画，收益最大、风险最低 |
| 跨页状态语言 | 定义统一「已收藏/未读」视觉语言（建议两页都用「左侧主色竖条 + 星标变色」），从 token/类收敛 | P2-2 | 消除跨页认知割裂 |
| 玻璃模糊治理 | 桌面 `.dd-panel`/`.link-menu` 在未锁滚动时改用不透明实底（参考移动 `.dd-sheet` 的 `var(--bg)`），仅 `lockPageScroll` 时启用模糊；合并 mask/panel 双重模糊为单层 | P2-3 / P3-3 / P3-4 | 消除长列表滚动重采样卡顿风险 |
| 响应式缝隙 | 卡片标题退场阈值由 `≤360` 提前到 `≤390`，或缩短 361–414 区间控件，消除折行带 | P2-4 | 覆盖无真机但可缩放的窗口宽度 |
| 可访问性 | 灯箱补 `keydown(Esc)` + 初始焦点 + 焦点陷阱（复用 `ConfirmDialog`）；`Dropdown` 折叠组改 `role="group"`+`aria-expanded`，listbox 子节点只放 `option`；整卡语义化可聚焦 | P2-1 / P3-5 / P3-6 | 键盘/读屏可达 |
| 令牌治理 | 合并分散的二次定义到统一段；统一容器底色令牌；收敛复制/打开按钮尺寸与「已复制」显隐开关 | P3-1/2/9/10 | 降低维护漂移 |
| 暗色拟态增强 | 暗色主题高光由 `.05` 提到 `.06~.08`、或卡片底与 bg 拉开一档，改善层级 | 视觉（暗色） | 暗色下浮起感回归 |
| 无图卡片 | 无图时收紧媒体区或加统一占位，避免大片留白 | P3-11 | 卡片墙节奏一致 |
| 测试覆盖补强 | 将本视觉回归脚本固化为正式测试（截图 diff + 关键计算样式断言），进 `tests/ui` | 全局 | 覆盖 jsdom 盲区，防回归 |

## 6. 修复优先级（用户已确认，四项全选）

1. **P1 动效令牌**（先做，3 行，收益最大）
2. **可访问性补全**（灯箱 Esc/焦点、listbox、整卡键盘）
3. **跨页状态统一**（收藏/未读视觉语言）
4. **玻璃模糊治理**（桌面下拉/链接菜单去模糊 + 合并双模糊）

建议按上述顺序分 4 个独立提交推进；每项均可用现有 UI 回归 + 本视觉回归脚本双重验证。

## 7. 待确认问题（开放）

1. **暗色拟态增强**：提高暗色高光会与 1.4.0「降阴影（评审 #9）」的意图拉扯——是否接受仅对**暗色**主题回补高光/拉开层级？
2. **跨页状态语言选型**：统一采用「左侧主色竖条 + 星标变色」（卡片页现状），还是「仅星标变色」（文章页现状）？
3. **玻璃模糊治理方式**：桌面下拉/链接菜单改为**不透明实底**（简单、稳），还是改为**打开时锁滚动**（保留模糊但需管理多弹层滚动锁）？
4. **灯箱可访问性**：是否纳入本轮「可访问性」批次一并修（涉及 `Overlays.jsx` 交互逻辑，需回归键盘路径）？
5. **无图卡片**：加统一占位，还是仅收紧媒体区高度？
6. **视觉回归固化**：是否把 `.workbuddy/scratch/visual-check.mjs` 整理进 `tests/` 作为长期守门（需处理 Edge 依赖与截图基线存储）？
