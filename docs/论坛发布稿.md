# 笺川 FeedLore：一个把「订阅 → 阅读 → 沉淀」收在一处的自托管 RSS 阅读器

**一条 compose 命令起好，装完不用再管更新。**

- 在线演示：**https://read.9610000.xyz** （账户 `demo` / 密码 `demo`，功能全部可点）
- 源码：**https://github.com/chensnails/FeedLore** （MIT）
- 形态：单容器 + PostgreSQL，无广告、无遥测、页面零第三方请求

![文章阅读页](https://raw.githubusercontent.com/chensnails/FeedLore/main/docs/screenshots/02-reader.png)

## 为什么又写一个 RSS 阅读器

我自己订阅里有一大半是「资源向」的内容：剧集、软件、网盘分享、带提取码的长帖。这类东西在传统的阅读器里被压成一行标题，看图要跳回源站，跳回去还得翻评论区。所以我把它拆成两个视图：

- **文章页**是常规阅读器：左边频道（按分组），右边列表，点标题就地展开全文，图片按原文顺序内联。
- **卡片墙**是资源视图：网格 / 列表卡片，带封面、标签、大小，点卡片直接弹详情读全文，收藏留在这一层。

两个视图互相指路 —— 在卡片详情里点「在文章页查看」，会切到文章页、滚到那一条、让它闪一下描边，不用自己在几百条里翻。

![卡片墙](https://raw.githubusercontent.com/chensnails/FeedLore/main/docs/screenshots/03-cards.png)

## 你会用到的功能

| 方面 | 具体做法 |
| --- | --- |
| 阅读 | 就地展开全文、已读 / 未读 / 收藏、服务端检索（标题 / 摘要 / 正文 / 标签）、自动刷新、快捷键面板 |
| 订阅 | RSS / Atom 粘贴添加、OPML 导入导出（含分组、自动去重）、频道重命名、**订阅地址可改**、分组重命名与拖拽排序、单频道抓取频率 |
| 抓取 | ETag / Last-Modified 省流量、按条数与天数清理旧条目、**连续失败的频道自动停用并提示**（不会一直报错刷屏） |
| 过滤 | 每个账号一套规则：关键词或正则，选「只收」或「屏蔽」，可只匹配标题 / 摘要 / 正文，在写库**之前**逐人生效 |
| 图片 | 外链图统一经自家 `/api/img` 代理，源站防盗链也不裂图；浏览器不会向源站直连 |
| 外观 | 4 套主题（跟随系统 / 浅色 / CommaFeed 暗色 / GitHub 暗黑）× 6 套主色，字号 / 字体 / 行高 / 阅读宽度即时生效 |
| 多用户 | 管理员建号，无开放注册；每人独立订阅源、已读、收藏、过滤规则与模型 Key；同一 URL 各存一份互不干扰 |
| 手机端 | 窄屏弹层一律整屏推入、可下拉手势关闭；HTTPS 下「添加到主屏幕」装成 App |
| 更新 | 「设置 → 关于」查新版本 + 一键更新；配 Watchtower 则推 tag 自动滚动升级 |

![卡片详情弹窗](https://raw.githubusercontent.com/chensnails/FeedLore/main/docs/screenshots/04-card-detail.png)

可选的 **AI 日报**：想用的话在「设置 → 模型」填自己的大模型 Key，就能按账号把过去 24 小时的新条目整理成中文简报。不配 Key 不影响任何其它功能，也没有任何默认调用的第三方服务。

## 部署

需要 Docker（含 Compose）。镜像模式同时出 `amd64` / `arm64`，树莓派和 ARM 云主机都能跑。

```bash
git clone https://github.com/chensnails/FeedLore.git
cd FeedLore
cp .env.example .env

# ⚠️ 一定要换掉默认密码
sed -i "s#^PG_PASSWORD=.*#PG_PASSWORD=$(tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 32)#" .env
sed -i "s|^WATCHTOWER_HTTP_API_TOKEN=.*|WATCHTOWER_HTTP_API_TOKEN=$(openssl rand -hex 32)|" .env

docker compose -f docker-compose.release.yml up -d
```

打开 `http://<主机>:3210`，首次启动的默认账号是 `admin / admin`，登录后到「设置 → 账号」改掉。之后「设置 → 数据源」粘 RSS 地址或导入 OPML 就能开始读。

想改代码就走源码模式（`docker compose up -d --build`）；两种模式的容器名 / 数据卷 / 网络完全一致，随时互切、数据零迁移。

## 技术上没什么惊喜

后端 Node 22 原生 `http`，不引框架；数据层 `pg` 直连，没有 ORM；前端 Vite + React 19，视图与内核之间是一个 `core` 单例桥，共享状态驱动重绘。整个应用一个镜像、一个进程、一个数据库。

测试是这套代码敢自动更新的原因：`npm test` 跑 260 多项 UI 回归（jsdom 里真点按钮、真发事件，含手势与弹层形态的静态守卫）+ 77 项服务端单测（加密、过滤、分页、权限），再加部署守卫（Dockerfile 文件清单、compose 契约）。

## 已知边界（免得你踩了来提 Issue）

- **不开放注册**：定位就是个人 / 小圈子，账号由管理员建。
- **没有原生 App**：手机端是 PWA，Service Worker 只缓存外壳，`/api` 一律网络优先，所以离线能打开界面但读不到新内容。
- **AI 日报要自备 Key**：站点默认可以不开，开了也只按账号用你自己的 Key。
- **演示库会重置**：`demo` 账户是共享的，别把重要订阅放进去。
- **备份只有一条路**：数据全在 PostgreSQL 数据卷里，自己定期备份（生产环境请务必先确认这条已经做了）。
